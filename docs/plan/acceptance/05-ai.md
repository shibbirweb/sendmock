# Acceptance: AI integration (AI)

Plan: [14-ai-integration.md](../14-ai-integration.md). Rules for IDs, ticking and tests: [README.md](README.md).

## AI-01 CLI

Phase 0 (skeleton), then every phase for its commands.

- [x] AI-01.1 Every operation in the registry has a CLI command (parity check passes). (#48)
- [x] AI-01.2 `--json` output is stable and documented; it is the default when stdout is not a TTY. (#48)
- [x] AI-01.3 Exit codes are `0` ok, `1` error, `2` usage, `3` not found, `4` timeout, `5` assertion failed. (#48)
- [x] AI-01.4 Destructive commands refuse to run without `--yes`; no command prompts unless `--interactive`. (#48)
- [x] AI-01.5 `sendmock help --all --json` lists the full command tree. (#48)

## AI-02 MCP server tools

Phase 1 onwards.

- [x] AI-02.1 `sendmock mcp` (stdio) and `/mcp` (streamable HTTP) expose a tool for every operation, with input schemas generated from the registry. (#48)
- [x] AI-02.2 Tools carry correct `readOnlyHint`, `destructiveHint` and `idempotentHint` annotations. (#48)
- [x] AI-02.3 `--toolsets` limits the exposed tools; `--read-only` hides every write tool. (#48)
- [x] AI-02.4 Secrets are never returned by any tool. (#48)
- [x] AI-02.5 `--embedded` starts an in-process server when none is running. (#48)

## AI-05 Agent skill and `sendmock ai install`

Phase 4 (skill, install), Phase 5 (plugin, evals).

- [x] AI-05.1 `sendmock ai skill` outputs the skill matching the binary version.
- [x] AI-05.2 `sendmock ai install --target` writes correct MCP config and instructions for Claude Code, Codex, Cursor, Gemini CLI and VS Code, shows a diff, and asks before writing.
- [x] AI-05.3 An agent in Claude Code and in Codex completes the example session (configure app, capture OTP, set up an inbound webhook) using only the skill and tools. (#48)
- [x] AI-05.4 Items created through CLI or MCP are tagged `created_by` and shown with a badge in the UI.
- [x] AI-05.5 The Claude Code plugin installs from the repository's marketplace with the skill and the MCP server, its manifests pass `claude plugin validate`, and its skill is the same as `sendmock ai skill`. (#48)
- [x] AI-05.6 `server.json` passes the MCP registry's schema, names the npm package and the image with the version of the release, and the stable release publishes it to the registry. (#48)
- [ ] AI-05.7 The skill has evals (a task, a seed, the end state checked through the API); a workflow runs them with Claude Code against a release binary and reports each one, and CI checks every eval is well formed.
- [ ] AI-05.8 SendMock is listed in the GitHub MCP Registry (`github.com/mcp`), which takes it from the official MCP registry (AI-05.6), and installs from it.
- [x] AI-05.9 (added 2026-11-07, owner request) An agent can start SendMock through npx with nothing installed: `npx sendmock ai install --target <agent>` writes configurations that run `npx -y sendmock mcp` (and `--npx` does so from an installed binary), `GET /ai/agents` gives each agent's npx install command and configuration next to the installed ones, and Settings > Connection lets you choose between them. (#48)
