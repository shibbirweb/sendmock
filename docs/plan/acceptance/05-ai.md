## AI-07 Saved scenarios

1.3.0 (A18), planned 2026-11-20 by owner decision: scenarios are stored so a setup can carry them. Plan: [32-after-1-0.md](../32-after-1-0.md#saved-scenarios-ai-07) (A18).

- [x] AI-07.1 A scenario is saved with a unique name, an optional description and its file, then listed, opened, edited, renamed and deleted, on the UI, REST, CLI and MCP; saving checks the file as `scenario validate` does and refuses an invalid one with its errors by step.
- [x] AI-07.2 A saved scenario runs by its id or name (`POST /scenarios/{scenarioId}/run`, `sendmock scenario run-saved <scenarioId>`, `sendmock_scenario_run` with `scenario_id`) and answers the same report as running its file.
- [x] AI-07.3 The Scenarios screen lists the saved scenarios beside the editor, opens one into the editor, saves (and saves as) what the editor holds, deletes after a confirmation, and marks unsaved changes while the editor differs from the saved file.
- [x] AI-07.4 Saved scenarios are part of a setup: exported as `[[scenarios]]` with their steps, applied by name on import, and restored by reset when the seed holds them.
