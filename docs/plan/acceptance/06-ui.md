# Acceptance: Web UI (UI)

Plan: [07-ui.md](../07-ui.md), mock layer in [11-roadmap.md](../11-roadmap.md#how-the-mock-layer-works). Screen-specific criteria live with each feature (EM, SM, VF, WH, HC); these cover the app as a whole. Rules for IDs, ticking and tests: [README.md](README.md).

## UI-01 App shell

Phase U0.

- [ ] UI-01.1 The sidebar, three-pane layout and responsive collapse work from 360 px to 2560 px wide.
- [x] UI-01.2 Theme follows the OS by default and can be switched to dark or light; the choice persists. (044db8b)
- [x] UI-01.3 Every documented keyboard shortcut works, `?` lists them, and `Cmd/Ctrl+K` opens the command palette. (044db8b)
- [x] UI-01.4 Live connection status and version are shown in the sidebar. (f8209c5)

## UI-02 Mock layer

Phase U0.

- [x] UI-02.1 With `VITE_API_MODE=mock` every screen works with no backend running. (f8209c5)
- [ ] UI-02.2 Mutations change mock state (delete, create, replay) and survive navigation.
- [ ] UI-02.3 The dev toolbar toggles latency, errors, empty state, large data and realtime events, and each screen handles each condition.
- [x] UI-02.4 No component imports fixtures or the mock DB directly (lint rule). (4f8d212)
- [ ] UI-02.5 Switching to `live` needs no component changes.

## UI-03 Overview dashboard

Phase U1.

- [ ] UI-03.1 Counts, webhook success rate, latency and recent failures are shown and update live.
- [ ] UI-03.2 Each failure links to its delivery.
- [ ] UI-03.3 The 24-hour activity chart stacks emails, SMS and HTTP requests per hour with a legend; hover and arrow keys show every series for that hour, and a table view shows the same numbers.
- [ ] UI-03.4 Each webhook endpoint shows its deliveries, success-rate meter, p50 / p95 latency, retries and top failure codes.
- [ ] UI-03.5 Stat tiles show totals and today's counts, and the connect card copies the SMTP address and API base URL.

## UI-04 Empty states and onboarding

Phase U1.

- [ ] UI-04.1 Every list has an empty state with "how to connect" instructions showing this instance's real host and ports (container hostnames in Docker).
- [ ] UI-04.2 "Send sample" creates a sample item so the screen can be explored.
- [ ] UI-04.3 The "Where does your app run?" choice changes the host on every how to connect card, is remembered, and is shared with Settings > Connection; it defaults to the Compose host when SendMock runs in a container.
- [ ] UI-04.4 A list whose search or filter matches nothing says so and offers Clear filter instead of the onboarding card.

## UI-11 Every feature in every way

Phase U3. Plan: [20-surface-parity.md](../20-surface-parity.md).

- [ ] UI-11.1 Every operation in the endpoint registry has a surface catalogue entry naming its CLI command, MCP tool (or MCP resource) and UI place; the only operations without an MCP tool are the two secret reveals, each with its reason; a test fails otherwise.
- [ ] UI-11.2 Every CLI command and MCP tool named in [14-ai-integration.md](../14-ai-integration.md) maps to a catalogue entry (`sendmock serve` and `sendmock mcp` start the servers and `sendmock help` prints help; they are the only commands outside it); a test fails on an unmapped name.
- [ ] UI-11.3 The spec carries `x-sendmock-cli`, `x-sendmock-mcp` and `x-sendmock-ui` on every operation, and the API reference shows the CLI command and MCP tool on every operation.
- [ ] UI-11.4 Every "From the CLI, API and AI" row in the user guide has all three cells, its API cell links to an operation in the spec, and its CLI and MCP names match the catalogue.
- [ ] UI-11.5 The new REST operations (wait helpers, `/otp`, `/links`, `/emails/latest`, `/emails/inbound`, `/send/raw`, `/events/recent`, `/integrations/{stack}`, `/scenarios`, `/ai`, tag and forward rules, outcome tests, payment test cards) are in the registry and the spec, answered by the mock in Demo mode and callable from the playground.
- [ ] UI-11.6 The new UI works: the Scenarios screen validates and runs a scenario step by step; Import .eml stores a message as sent or incoming; the tag and auto-forward rule cards create, order, switch off and delete rules that apply to new mail; the AI agents card shows the install command and MCP configuration per agent.
- [ ] UI-11.7 A Surface parity workflow runs on every pull request and every push to `develop` and `main`, fails when any operation lacks a CLI command, an MCP tool (outside the recorded exemption) or a UI place, and writes a per-area summary to the job page.
